# ADR-0002: v0.1 Data Boundary

Status: Accepted for v0.1.0
Date: 2026-09-29

## Decision

v0.1.0 stores only transient authenticated-session state and exposes a small safe operational state endpoint.

It deliberately does not introduce a production database or object archive.

## Why

The first release exists to prove the end-to-end command-center flow without creating a false impression that a free-tier environment is ready for banking, personnel, trade-secret or irreplaceable corporate data.

Introducing PostgreSQL and object storage before the identity, backup, classification and recovery controls are ready would increase operational surface without delivering the required safety evidence.

## Consequences

- active sessions are lost when the service restarts
- the current operational state is process-derived
- no critical company records are stored
- future persistence must be introduced through a deliberate schema/data-boundary change

## Next persistence gate

Before persistent private data is introduced, define:
- data classification
- database ownership and access model
- migration/recovery procedure
- backup strategy and restore drill
- audit requirements
- retention/deletion policy
- secret/key-management strategy
- production hosting plan

PostgreSQL remains the planned relational baseline once that gate is satisfied.
