# ADR-0001: v0.1 Member Authentication Boundary

Status: Accepted for v0.1.0
Date: 2026-09-29

## Decision

v0.1.0 uses GitHub OAuth 2.0 Authorization Code flow with PKCE as the external identity boundary. The backend retains only the minimum member identity needed for the session and authorizes access using an explicit GyLiber GitHub-login allowlist.

## Why

A bespoke password database would add credential storage, password reset, recovery and breach-management responsibilities to the first release. GitHub provides an established identity surface, while the allowlist prevents arbitrary GitHub users from entering the private hub.

The OAuth client requests only the read:user scope. GitHub credentials are never handled as GyLiber application passwords.

## Security properties

- authorization-code flow
- PKCE
- OAuth state bound to the server session
- private, HttpOnly session cookie
- short inactivity expiry
- server-side member authorization
- no access-token persistence in application storage

## Consequence

The v0.1 session store is in memory. A process restart invalidates active sessions. This is acceptable for the first non-critical release but must be replaced by a durable session/authentication architecture before the platform becomes a multi-instance private production system.

## Future

The identity domain should move toward a mature OIDC provider with WebAuthn/passkeys, centralized lifecycle management, strong recovery, session/device visibility and fine-grained claims/policies before high-impact data is onboarded.
