# Contributing to GyLiber Command Center

## Before changing code

Read:
- README.md
- docs/requirements/REQUIREMENTS.md
- docs/security/SECURITY.md
- docs/governance/DEVELOPMENT.md

## Commit format

Use Conventional Commits.

Examples:

`feat: add resource status module`
`fix: reject unauthorized resource access`
`test: cover expired session handling`
`docs: record architecture decision`

## Pull requests

Keep each pull request focused on one coherent unit. Include verification evidence and identify the highest data classification touched.

Never include secrets, production credentials, private keys, real personnel records, customer data or other restricted information in code, issues, pull requests or test fixtures.

## Security reports

Do not report suspected vulnerabilities in a public issue. Follow SECURITY.md.

## AI-assisted work

AI may assist with development, but the contributor remains responsible for validating code, dependencies, tests, security behavior and licensing.
